## Mission Statement

Transform Commander TJR from an implementation advisor into a decision-making engine.

MSN-0008 delivered the infrastructure for collaborative specialist intelligence.
MSN-0009 elevates the quality of what that infrastructure produces.

When Captain TJR asks Commander a strategic question today, the response describes
how to execute options. After MSN-0009, the response recommends a specific direction,
explains why, quantifies the opportunity cost of not choosing it, and explicitly
resolves any tension raised by the Expert Challenge review.

---

## Strategic Objective

USS TJR's primary purpose is to help Captain TJR make better decisions.

A system that produces implementation guidance when asked a strategic question is
technically operational but strategically incomplete. MSN-0009 closes the gap between
what Commander currently produces and what Captain TJR actually needs.

---

## Scope

### In Scope

**1. Strategic Recommendation Mode**
Commander produces a clear, named recommendation for strategic questions — not a
balanced presentation of options. "Do X because of Y" rather than "here are three things
you could do." Options are presented as context, not as the conclusion.

**2. Opportunity Cost Analysis**
Every strategic recommendation includes explicit acknowledgment of what is being
traded off. If Commander recommends building Voice Core before the Decision Register,
it must state what is lost by not building the Decision Register first.

**3. Bottleneck Identification**
For questions about priorities and sequencing, Commander identifies what is currently
blocking the most downstream value — the single highest-leverage point in the current
situation — and names it explicitly.

**4. Recommendation Weighting**
When multiple specialists contribute to a collaboration, Commander's synthesis reflects
whose perspective is most relevant to the specific question. A health question should
weight Medical Officer input more heavily than Chief Engineer input, even if both
specialists contribute.

**5. Decision Modes**
Commander should recognise the type of question being asked and respond accordingly:

| Mode | Trigger | Commander Response Style |
|---|---|---|
| Strategic Decision | "Should I...", "What should I...", "Is it worth..." | Named recommendation with rationale and opportunity cost |
| Implementation Guidance | "How do I...", "What is the best way to..." | Structured guidance with options and trade-offs |
| Analysis Request | "Assess...", "Review...", "What are the risks of..." | Structured analysis without forcing a recommendation |
| Information Query | "What is...", "Where is...", "Show me..." | Direct answer from knowledge base |

**6. Expert Challenge Resolution**
When a Challenge Review specialist disagrees with the primary recommendation,
Commander's final synthesis must explicitly state:
- Whether the challenge is accepted, rejected, or partially accepted
- The reasoning behind the resolution
- How the final recommendation reflects the challenge outcome

**7. Operational Visibility Phase 1 (Quick Wins)**
Create the Missions database and Decision Register in Notion using the MSN-0008D/E
architecture. Manual entry only — no automation required in this mission.
Build the Command Centre homepage.
Populate with current mission state.

This is included in MSN-0009 because it is low-effort and provides immediate daily value
that improves the experience of using Commander's improved outputs.

## Success Criteria

MSN-0009 is complete when:

1. Captain TJR asks "Should I build X or Y next?" and Commander responds with a named recommendation and explicit opportunity cost statement — not a list of pros and cons.

2. Commander identifies which item in the current backlog is the highest-leverage bottleneck and names it without being asked to do so when a priority question is posed.

3. When a Challenge Review specialist disagrees with a primary recommendation, Commander's synthesis states whether the challenge was accepted or rejected and why — not a diplomatic hedge.

4. The confidence level of every Commander recommendation is visible to Captain TJR.

5. The Notion Command Centre homepage is operational and Captain TJR opens it daily.

6. At least five decisions are recorded in the Notion Decision Register within the first week of operation.

## Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Synthesis prompt changes degrade quality in some domains | Medium | Test against 10 representative questions across domains before deploying |
| Decision mode classifier misroutes questions | Medium | Default to Strategic Decision mode on ambiguity — a recommendation is always useful, even if not requested |
| Captain TJR does not adopt Decision Register habit | Medium | Keep register entry friction minimal. Commander should prompt for decision entry after delivering recommendations. |
| Notion operational visibility becomes stale immediately | Low | Phase 1 is manual — set a weekly discipline of updating. Automation in MSN-0011 eliminates this. |

## Accepted Trade-offs

- MSN-0009 does not fix the parallel execution latency issue (TD-001). That is MSN-0010. Commander may still be slow on complex collaboration requests during MSN-0009.
- Operational visibility in Phase 1 is manual. Automation requires MSN-0011.
- The synthesis quality improvement is prompt engineering, not architectural change. It will require iteration and testing. The first version will not be perfect.
